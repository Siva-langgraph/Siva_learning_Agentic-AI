# Production deployment runbook

1. Provision managed PostgreSQL with TLS, private networking, backups, monitoring and a least-privilege read-only role.
2. Store `DATABASE_URL`, `OPENAI_API_KEY` and `APP_API_KEY` in the platform secret store; never bake them into images.
3. Set `APP_ENV=production`, `OPENAI_MODEL`, and `ALLOWED_ORIGINS`.
4. Put the API behind HTTPS ingress/API Gateway; configure identity-provider authentication, WAF/rate limits and request quotas.
5. Build and scan the image in CI, pin dependencies, deploy to staging, and run smoke tests before production.
6. Verify invalid API keys are rejected, tools cannot execute raw SQL, query timeouts work, and the database role is read-only.
7. Configure logs, metrics, tracing, alerts, backups and rollback to the last known-good image.

The model chooses a fixed tool. SQL is defined in application code, not generated by the model. SQLite seed data is local-demo only; production must use PostgreSQL. The SSE endpoint emits `status`, `progress`, `done`, or `error`; disable proxy buffering for streaming.
